Decision Lab 整体方案

愿景｜让处于不同业务阶段、具有不同 AI 渗透深度的企业，都能在真实生产中建立持续运转的智能化转型飞轮。

Decision Lab 帮助业务团队梳理目标、职责、规则与例外，用共同度量衡验证智能体表现、改进组织协作，再以生产结果检验调整。平台助推业务升级。市场选择、业务策略、经营投入与最终结果由企业承担。

一　问题定位

1.1 企业缺少什么

不同企业在不同市场下会选择不同策略。即便在同一个集团，有的 BU 更看重增长，有的更看重回款、服务质量或成本。共同缺口是缺少一套可在生产中持续使用的度量衡，把业务目标、过程约束、组织协作和执行结果放到同一套可复核的评价流程中。一次正常的工具调用只能说明操作发生了，业务验收还需要确认结果、影响与例外处理是否符合当下策略。

1.2 企业在买什么

业务负责人和业务数智化负责人为更清晰的业务规则、更快的改进验证和更可控的委托范围付费。智能体评测是实现手段。通过开始评价一次实际工作，业务团队会被迫明确交付标准、责任归属、冲突优先级和例外，进而有依据调整工作本身。平台对测量的可追溯性与方法质量负责，经营团队对策略选择、授权和业务结果负责。

1.3 企业智能架构中的位置

职能负责的事实与决定与 Decision Lab 的接口
业务治理定义职责、规则、风险容忍度和授权，批准发布、接管及例外。提供业务判据，接收可复核的验证结果与授权建议。
AI 操作系统与业务系统执行 Agent 与人工流程，实施权限、发布、停止和回滚。提供版本、执行入口和实际业务状态。
现有可观测系统采集与查询轨迹、日志、指标。经授权导入所需证据，并保留来源关联。
Decision Lab定义评测任务，组织证据与复测，形成能力画像、诊断和版本比较。把证据链和结论交给业务治理与发布系统使用。

已有工程基础包括版本化 CLI、离线预检、幂等实验创建与可恢复的单机 Worker。历史 CLEF 实测和公开基准子集验证支撑当前原型。Forge 提供生产实践参考，尤其是外部轨迹接入、混合评分和人工复核。Decision Lab 独立实现自己的领域模型、接口和运行链路。

二　解决方案价值

2.1 组织如何使用这套度量衡

借鉴的人类组织知识在平台里的表达帮助组织改善什么
组织行为学中的角色、职责与协作用职责、目标、授权、交接、人工接管与团队结果设计评测。涉及多个 Agent 或人机交接时，同时验证个人角色与端到端流程。发现职责重叠、交接断点、激励与任务目标冲突，区分个体改进和流程改进。
MBTI 的多维描述方式为某个版本在特定业务情境下形成画像，例如自主完成、优先求证、主动转交及适用边界。维度由业务任务定义，结论绑定可观察行为与样本。便于分配工作、组合角色和发现能力缺口。画像按情境和版本更新，用证据支持分工。

集团共用的是度量方法：目标关联、评测条件、证据口径、样本范围和复测规则。各 BU 按自身市场、策略和风险设定指标与权衡。同一种成功率只有在业务定义、样本和统计单位足够可比时才可横向比较。

2.2 生产转型飞轮与资产沉淀

  1. 梳理业务。 业务方从目标、职责、现行流程和例外中定义可验证的成功条件，并建立人工或规则基线。
  2. 度量生产。 接入经授权的轨迹、业务状态和延迟出现的结果，从典型业务、异常和高风险边界建立复测任务。
  3. 判断该改哪里。 同一套业务要求下验证 Agent 改进。业务要求本身有冲突或效果不佳时，由业务方修订规则、协作方式与授权，形成独立版本。
  4. 复测并回看结果。 应用团队验证改动，业务方及发布方依权限决定上线、维持或收回授权。后续业务结果验证变化是否兑现，新例外再进入用例集。

每转一轮，应留下可复用的业务资产：职责与规则、例外、用例、证据、决定及其结果。Agent、模型或团队更换之后，企业仍能沿这些资产持续学习。规则遵守程度和经营效果分别评价，后者的归因需要与问题相匹配的对照。

2.3 企业智能化架构双维矩阵

以 BU 内的业务职责或流程作为实际评估单元。X 轴业务生命周期决定投入方式与运营节奏。Y 轴 AI 参与深度以所承担的业务决策和动作权限为主判据，另记系统耦合、数据敏感度、动作可逆性和接管能力。坐标用于选治理和部署规格。集团统一证据与审计契约，各 BU 定义任务、判据、授权和复核权。

2.4 各方责任、权限与收益

利益相关方负责提供与维护决定权获得的收益
业务负责人 / 数智化负责人业务目标、规则与例外、效果指标、风险容忍度，以及规则修订后的业务复核。确定策略、职责委托和业务验收，承担经营结果。规则清晰、可委托范围可见，能判断迭代投入是否值得。
一线业务人员 / 领域专家提交典型与异常案例，解释业务语义，复核疑难样本和人工接管结果。按业务授权处理例外，确认样本与判据的解释。减少重复返工，保留专业经验，改进人机分工。
生产 Agent 应用团队被测版本、受控运行入口、运行快照、问题修复和复测。选择实现改进，在业务授权内提交候选版本。更快定位失败链，验证修复与回归，减少重复排障。
平台、数据与运维团队证据来源、访问与留存边界、生产接管与恢复方式。依据数据和运行职责批准接口与环境，执行既定处置。跨 Agent 和 Harness 统一问题分流，缩短定位与恢复时间。
治理与发布责任人发布门槛、审批、例外处理和回滚要求。按授权审批发布、暂停或回滚实际部署。可复核的变更依据与责任记录。
Decision Lab 团队度量契约、证据质量、评分与诊断可追溯、复测与结果交付。声明什么可比、证据是否充分，给出评价与建议。沉淀可跨 BU 复用的接入、评价与诊断能力。

三　架构设计

3.1 从经营目标到评测证据

架构以业务职责连接企业的两条改进路径。上游保留目标、规则与授权语义，中间用评测任务把这些要求变成可核验的判据，下游把评价交回原有决策系统。连接器、执行适配器、评分器和领域指标按契约扩展，共用证据来源、版本关联、状态语义与审计。

领域关键对象必须守住的规则
业务语义业务目标、业务职责、规则版本、授权策略、评测任务与用例版本一项职责可拆成多项任务。任务明确适用情境、成功条件、关键约束和所需证据。业务责任人确认规则与例外。
被测方案Agent 或模型方案版本、声明配置、实际运行快照保留已知依赖版本与未知声明，支持单模型、规则、混合策略和多步 Agent。
实验与证据实验计划、试验、尝试、调用、观察与业务结果执行前冻结用例、被测方案、协议和预算。导入与受控运行共用证据契约，显式记录来源和完整度。试验、平台重试、模型调用分别计数。
评价与分析逐项评价、诊断、报告、能力画像、业务结果对比评价绑定证据和评分版本。重评分追加历史。报告声明分母、缺失、适用范围与证据限制。遵守规则、协作效率和实际业务结果分别呈现。
治理协同回归结论、准入证据、授权建议、复核记录业务结论绑定职责、规则、被测方案及适用条件。授权决定有责任人、证据引用和复测条件。比较前验证可比性。授权生效由业务或治理系统决定。

一次变更至少要能区分三种情况：Agent 变了、业务规则变了、评分口径变了。三者独立版本化。成对比较需明确条件一致的用例、变更因素、缺失和关键切片。

3.2 六层 Agent 架构如何进入评测

被测层可关联证据可验证问题
Agent 定义目标、权限、配置与引用版本实际执行是否符合职责与权限。
Harness分支、停止、重试、交接和上下文拼装事件编排是否提前停止、重复执行或错误交接。
Skill / Tool调用选择、参数、版本、返回及外部状态区分选错、传错、返回错误或使用错误。
会话上下文与短期记忆受权的上下文快照、指纹或引用决策时是否具备必要信息。
长期记忆、知识与本体检索命中、适用版本、来源与时效区分未检索到、资料过期和使用错误。
执行单元、模型与基础设施模型版本或未知声明、截断、超时和部署条件区分可观察的运行限制与待验证的模型行为。

3.3 接入、执行和评分契约

  • 证据接入。 通过可插拔连接器对接现有轨迹、业务结果或外部评测记录。契约包含租户、来源、任务/试验关联、版本和证据可见性。按授权采用脱敏快照或引用，记录引用过期与来源版本变化。
  • 受控执行。 通过适配器接单步模型、外部 Agent 或受控环境。持久 Worker 管理领取、预算、取消及恢复。复测有外部副作用时，使用环境隔离或模拟的测试权限。已登记调用结果未知时保留事实与预算占用。
  • 可插拔评价。 每种评分器声明输入证据和版本，可接规则、业务约束、人工复核与校准后的模型裁判。评分器故障、证据不足和任务未通过分别表达。确定性重评分复用原始证据。模型裁判使用独立预算。
  • 共享应用服务。 CLI、界面和未来的 API 共用领域规则、权限和状态语义。以任务和证据能力做适配校验，允许部分轨迹和异构部署。新的适配形态通过契约测试验证兼容。

四　落地规划

4.1 设计推进与生产验证

  1. 评审整体方案。 先确认愿景、双维矩阵、各方责任与决策权，以及生产度量如何反馈给业务。以场景风险和可用数据确定后续验证范围。
  2. 验证度量内核。 用行业中立的单步决策与外部多步证据检验导入、版本比较、缺失判定、人工复核和重评分。验证同一内核能容纳不同业务判据。
  3. 在生产中验证组织学习。 选择拥有责任人、实际业务结果与合法接入方式的 BU。保留现行基线，先在限定范围内验证，通过一次真实改规则、改 Agent 或改授权的决定完成闭环。
  4. 验证跨 BU 复用。 选择不同生命周期或自治深度的业务，保留通用契约，允许自有指标、权限与复核节奏。对照接入成本和日常运营负担，检验联邦式设计。

4.2 交付团队如何协作

每个试点由业务负责人确认职责、可接受风险与衡量口径，应用团队提交运行清单和受控复测能力，数据与运维团队交付经授权的证据与异常接管安排。Decision Lab 团队产出可复核的评测证据，业务治理与发布责任人用原有权限流程处理验收、例外和实际变更。

交接时至少能对齐业务职责与规则版本、样例和适用条件、Agent 运行版本、轨迹与业务结果关联、判据与分母、决定与复测条件。业务代表能复核规则与结果，工程团队能重新运行或说明原因，发布方能把批准的范围关联到具体证据。

4.3 开工前的架构评审与验收依据

  • 领域与责任。 职责、任务、证据和授权决定能画出关联。业务规则和评分口径的维护者明确。
  • 数据与部署。 确认来源、权限、脱敏、保留期限、部署边界及受控执行方式。共享环境确认项目隔离与凭据范围。
  • 验证规格。 按职责定义证据覆盖、评测可靠性、预算、恢复和可追溯性要求。试点验证是否产生真实改变、是否能复测，以及是否能对照经营效果。至少验证缺证据、评分异常、任务中断与版本变化。
  • 演进与迁移。 梳理原型的能力复用、数据迁移、契约变更、回退和确认人。整体方案评审后再调整仓库层面的架构与实施计划。

待评审决定包括首发行业、首批接入协议与证据来源、部署拓扑、具体性能目标和第一阶段交付范围。

五　技术难题

现有原型已验证单机调度与部分模型评测。外部多轮证据、生产结果关联、跨项目隔离和业务归因是待验证的工程问题。

难题设计约束可检查的证据
策略差异与度量效度评价绑定业务目标、策略版本和适用条件。分开记录规则遵守、人工协作与经营效果，允许不同 BU 使用不同权重和阈值。人工复核争议样本，记录可比条件。能解释规则变更与 Agent 变更对结论的不同影响。
生产结果滞后与效果归因按业务事件关联后续结果，记录观察窗口、未观察到的结果及外部变化。根据决策重要性采用分组、分批或其他适当对照。能区分已观测差异和可归因效果。证据不足时该判断保持待验证。
画像与协作的有效性维度绑定可观察行为与适用情境，记录人员、Agent 和 Harness 的职责与交接。不同试验种类声明统计单位。用重复试验与实际交接结果复核画像，区分局部改善与端到端成功。
异构轨迹、字段缺失和版本漂移通用信封保留来源与版本，支持领域证据扩展。原始信息缺失要传到报告。样例轨迹映射覆盖、来源可回溯、缺失能被解释。
区分表象与根因区分首次偏差、疑因和复测支持的归因。用可观察行为、受控替换和外部状态校验。相同历史证据可复核，归因说明包含验证条件。
评分口径可信与指标被优化优先检查业务结果和硬约束。保留人工复核与独立测试集，按关键群组查看退化。分开报告评分覆盖、业务成功及结果未知。评分与人工判断的一致性、关键用例变化、各指标分母和测试分布可查。
重放副作用、故障和成本隔离测试环境，持久记录调用、额度和中断恢复。评测预算单独管控，区分被测调用与裁判调用。取消、回滚、重试与故障恢复有验证记录。
企业数据与联邦治理按 BU 管理任务与审批权，集团统一最小证据契约与审计。共享访问前验证授权、凭据与数据隔离。越权测试、保留与清理记录、导出范围、恢复演练。
