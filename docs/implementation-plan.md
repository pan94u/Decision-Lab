# Decision Lab 实施计划

更新：2026-11-01。已完成基底见第 4 节；当前建设 Phase 1，P1.1 已交付，其余待实现。各 session 的交付证据见 [logbook](logbook.md)。领域和机器入口约定以[架构设计](architecture.md)为准，本文只定义交付顺序、边界与验证证据。

## 1. 阶段目标与迭代方式

**Phase 1：让智能体通过稳定 CLI 和操作 Skill，完成一次有预算约束、可追溯、可恢复的评测。**

交付场景：智能体读取能力 → 从本地任务文件构造计划 → 离线预检 → 提交实验 → 查询或等待 → 读取报告与失败证据 → 对已有响应重评分。提交进程退出后，独立 Worker 继续执行；智能体依据持久 ID 接续工作。

本阶段定位为单机、单项目受信任操作者的工程交付，建立后续生产平台的机器操作基底。共享服务身份、完整回归准入和部署保障仍需后续切口，完成本阶段不等于满足全部生产判据。

以 session 为交付单元，每次选择一个最小完整用例，记录目标、完成条件、实际证据和剩余风险，写入 logbook 后提交推送；以周复盘优先级。下列里程碑按依赖排序，可以跨周；不预设未经估算的工期。使用临时库和 fake adapter 验证行为，真实 API 调用另行显式触发。

## 2. Phase 1 交付范围

### 2.1 最小业务闭环

| 环节 | 本阶段交付 | 边界 |
| --- | --- | --- |
| 发现与准备 | 版本化机器契约；适配器/任务/评价能力发现；任务文件与模型配置样例 | 复用已验证的 choice/classification 及受支持判据；CLEF 不支持的生成任务预检即拒绝 |
| 计划与预检 | 显式项目、操作者、方案、BenchmarkSpec、凭据引用、调用数与运行时限；返回指纹、问题清单和调用上界 | 本地 JSON 任务文件随计划冻结；不建设任务资产编辑平台；无定价时费用显示未知，不伪造预算保证 |
| 提交与执行 | 幂等创建；单 Worker 持久领取、租约、预算预留、取消及恢复 | 本机独立前台进程，由操作者或进程管理器启动；不提供多副本/分布式调度；未知在途请求不自动重发 |
| 观察与解释 | 按 ID 查进度、结构化报告、逐例错误与证据索引 | 区分排队、执行错误、结果未知、无效输出与有效但答错；报告保留未完成分母和协议兼容标记 |
| 重评分与接续 | 从已保存响应产生新评价修订，保留旧结果；客户端退出后按 ID 接续 | 重评分不调用模型；不增加基线管理和准入规则 |
| 平台界面 | 通过共用应用服务完成任务文件导入/预检、模型凭据引用配置、实验创建/取消、进度、报告和重评分 | 界面基础流程纳入本阶段；不重建完整任务编辑器，不形成浏览器权威队列 |
| 智能体操作 | 一份随版本维护的操作 Skill，使用上述 CLI | 先支持一种可实际验证的 Skill 宿主；业务规则和凭据留在平台；评测 Skill/智能体本身另立切口 |

预算以实际 Invocation 为计量单元，预留调用额度后才允许发请求；首期无自动网络重试。运行时限到达或取消后停止领取、尝试终止在途请求，并记录已知响应或结果未知。提供商可能已经执行或计费，不将取消解释为远端回滚。恢复已保存响应只补评价；租约过期且无响应的尝试标为 interrupted/outcome_unknown，等待显式处理。

### 2.2 计划中的 CLI 表面

能力发现、计划预检、实验创建与查询已交付，实际调用方式见 README；其余命令仍为草案，能力发现只公布已实现的命令。计划文件复用已有领域结构，以 JSON Schema 固化必填字段和版本；不另创一套命令专属评测模型。

| 命令草案 | 输入与主要结果 |
| --- | --- |
| `decision-lab capabilities --json` | 返回契约版本、任务/适配器/评价能力及限制，不列出凭据值 |
| `decision-lab plan validate --file plan.json --json` | 离线检查计划，返回规范化指纹、调用上界及结构化问题；不创建实验或请求模型 |
| `decision-lab experiment create --file plan.json --project PROJECT --idempotency-key KEY --json` | 校验后冻结并入队，返回持久 experimentId；相同键与不同指纹冲突 |
| `decision-lab experiment get --id ID --project PROJECT --json` | 返回冻结版本摘要、执行计数与状态；证据读取在 P1.3 增加 |
| `decision-lab experiment wait --id ID --timeout 60 --json` | 有界等待并返回最新状态；超时不取消实验 |
| `decision-lab experiment report --id ID --json` | 返回版本化报告及指标分母；原文通过显式证据选项读取 |
| `decision-lab experiment rescore --id ID --evaluation-file evaluation.json --idempotency-key KEY --json` | 对持久响应追加评价修订；重复请求去重，不覆盖旧评价 |
| `decision-lab experiment cancel --id ID --json` | 幂等记录取消意图和执行状态；返回仍在途的调用信息 |
| `decision-lab worker run` | 运行单 Worker；独立于创建/等待进程，诊断进入 stderr |

机器模式无交互提问；stdout 输出一个 JSON 结果，诊断与进度进入 stderr。统一信封包含 schemaVersion、requestId、data/error；稳定错误包含 code、message、details 和是否可重试，业务成绩位于报告中。退出码约定：0 为命令成功，2 为输入/预检问题，1 为运行错误，3 为等待超时；模型答错不改变命令成功码。Worker 是持续进程，不使用单次结果信封。

状态、报告和修改命令均携带明确项目上下文；本机操作者标识用于来源记录，不宣称已实现身份认证。Key 通过执行端配置和 credentialRef 关联，不出现在命令参数、计划、普通输出或持久证据中。预检检查引用格式及配置可用性，不将凭据发送到外部验证。

### 2.3 完成标准

使用真正的 CLI 子进程、临时数据库与确定性适配器完成以下验证；不能只调用内部函数证明入口可用。

1. 按机器契约发现能力、读取任务文件、预检、创建、等待、读取报告、重评分，全程不依赖页面或交互问答。
2. 预检无网络请求；CLEF 与不支持的任务组合在入队前拒绝。提供一份合法样例和一份能力冲突样例。
3. 重复提交仅创建一个实验；同键不同内容明确冲突；创建进程退出后独立 Worker 仍能完成，另一个进程按 ID 读取结果。
4. Worker 在响应已落盘、尚未评分时退出，重启只补评分；请求在途时退出则显式标为结果未知，不静默再发；过期代次不能覆盖当前结果。
5. 调用预算、运行时限和取消行为有可复现证据；等待超时不取消；未知及失败调用占用的额度不会被自动释放后重复消费。
6. 重评分追加评价版本且调用次数不增加；重评分命令重放不重复写入；报告对未完成、无效输出与答错分别计数。
7. 各命令 JSON 通过 schema 校验，stdout 无混杂日志，错误码/退出码可判断；输出、诊断和证据检查无凭据泄漏。
8. 平台界面通过同一应用服务完成导入、预检、创建、取消、查进度、报告与重评分；CLI 创建的实验可在页面读取，页面创建的实验可用 CLI 查询。
9. 操作 Skill 在选定宿主由智能体实际完成上述闭环，并对不支持任务和等待超时作正确接续；记录 CLI/Skill/宿主版本及命令轨迹。确定性脚本作持续回归，真实宿主演练作为集成证据，两者分别记录。

CLEF 既有实测用于证明适配器可用；本阶段不重复扩大 benchmark 样本。需要真实调用冒烟时，另行明确样本和调用上限，不纳入默认离线验收。

## 3. 落地顺序与本周切口

| 里程碑 | 最小可交付增量 | 完成依据 |

| P1.1 契约与应用入口（S001 已交付） | 提取共用应用用例；CLI 骨架、能力发现、计划预检、创建/读取；统一信封、错误与 JSON Schema | 两个独立 CLI 进程创建/读取同一冻结实验；预检拒绝不支持组合；重复提交一致；无需启动模型调用 |

## 4. 已完成基底与证据

- 状态：首个基底验证切口已完成，通过内部 CLI 驱动，尚未接入页面或后台队列。
- 证据：`npm test` 最近一次 20 项通过；`npm run build` 与 `npm run validate` 通过。`npm run benchmark:verify` 使用 72 个真实源样例展开 754 次受控执行，与固定参考实现核对 754 个整题结果、900 个判据结果及 16 个概率值，差异为 0；详见 [结果摘要](../benchmarks/verification-summary.json) 和 [源版本清单](../benchmarks/sources.json)。原始数据、SQLite 和完整记录位于 Git 忽略的 `artifacts/benchmark-verification/`。

## 5. 后续方向与计划维护

Phase 1 完成后按实际需求选择下一切口：在已互通的 CLI/Web 基础上形成可核验的基线/候选回归与准入；共享访问前补齐项目身份、授权和审计；生产交付前完成迁移、备份恢复、可观测性及明确容量下的故障演练。各项约束持续增量实现，不延后到发布前首次考虑。
