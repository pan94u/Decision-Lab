# Decision Lab 实施计划

更新：2026-11-01。当前处于设计整理，以下能力尚未实现。领域契约引用[架构第 3 章](architecture.md#3-领域架构)，生产判据引用[第 1.3 节](architecture.md#13-质量要求与生产判据)。

## 1. 迭代方式

以周为工作周期，每周选择一个最小完整用例，形成“问题/假设 → 实现 → 验证证据 → 复盘 → 下一切口”。周次是相对迭代顺序，不预设日历期限或承诺未经估算的工期；一个切口未满足完成条件时优先收尾。

每周只记录四件事：本周目标、完成条件、实际证据、剩余风险。任务按依赖顺序提交，保持现有应用可用；代码与数据迁移分开说明。使用临时数据与 fake adapter 验证正确性，真实 API 调用显式触发。周末只根据证据勾选完成，不根据“已写代码”结项。

## 2. 第一周：建立一条可信结果链

**目标：** 在服务端冻结一个类型化决策场景、方案及最小 BenchmarkSpec，通过 fake adapter 执行一次，把原文和版本化评分持久化，重启后能读取并重算。

这是生产基底中的一个完整切口。保留现有页面和调用方式，不同时扩展多模型、后台并发、门禁审批和任务编辑。当前 fake adapter 的结果仅标明为测试来源，不能成为真实模型成绩。

### 按顺序完成

| 任务 | 改动范围 | 完成条件与证据 |
| --- | --- | --- |
| W1-1 提取领域逻辑 | 从 engine.js 分离任务契约、输入投影、归一化与评价；明确 schema/protocol/normalizer/evaluator 版本；兼容现有页面 | 现有任务与评分行为保持；测试确认参考依据不进入模型输入、无效输出不会伪装为答错 |
| W1-2 验证并确定单机存储 | 为当前切口验证 SQLite 事务/唯一约束/重启读取；固定兼容运行时；加入 schema migrations 和 repository | 临时库验证事务失败不留半份实验，重复键被拒绝，重启读取一致；在架构第 5.3 节记录支持范围和重审条件 |
| W1-3 冻结最小实验 | 实现一个方案、一个场景、一轮实验；冻结 BenchmarkSpec，分开 trial 与 invocation；保留将来多方案所需的计划结构；保存 project/actor/来源、版本及输入指纹 | 修改原始任务或配置后旧实验不变；幂等创建返回同一实验；不在证据中保存凭据 |
| W1-4 保存并评价一次执行 | 服务端应用用例串联 Execution/Attempt、fake adapter、原文保存、评价修订 | 响应先保存；评分异常仍可读取原文；重算创建新评价记录、不调用适配器且不覆盖旧评分 |
| W1-5 暴露最小查询与用例入口 | 提供创建/执行/查询最小服务端入口，或先以内部 CLI 驱动；保持输入和输出契约明确 | 创建后返回可追踪 ID；进程重启后能按 ID 查询输入版本、原文和评价；接口不返回 Key |

建议提交边界：
1. `refactor: extract versioned decision evaluation domain`
2. `feat: persist immutable experiment snapshots`
3. `feat: record execution evidence and reproducible assessments`

### 周末验收用例

使用固定 fixture，经实际文件数据库和应用入口创建实验并执行：
1. 同一个创建请求重复提交，只有一份实验。
2. 原任务被修改，旧实验输入和版本仍一致。
3. 收到原文后主动制造评分失败，原始响应仍保留。
4. 结束并重启服务，再按 ID 读取该实验。
5. 从已保存响应重算，生成新评价修订；fake adapter 调用次数不增加。
6. 改变协议/提示或候选映射产生新指纹，旧报告不被标成同一协议；OOS 合法结果不被当作接口错误。
7. 同一场景含多个判据时分别保留逐项及整题结果；一次 trial 内多次 fake 调用不增加独立试验数。
8. 检查持久数据和导出结构中没有凭据。

最小契约检查使用 closed-choice、合法 OOS、多判据三类小 fixture，按架构第 3.3 节的反例验证抽象；fixture 标为自建或派生，不宣称官方成绩，不下载或执行整套 benchmark。

**完成证据：** 自动测试输出、可读实验 JSON、迁移/回退说明和一个按 ID 查询的示例；测试数据位于临时目录，不触碰用户真实记录。

### 第一周记录

- 状态：首个基底验证切口已完成，通过内部 CLI 驱动，尚未接入页面或后台队列。
- 证据：`npm test` 17 项通过；`npm run build` 与 `npm run validate` 通过。`npm run benchmark:verify` 使用 72 个真实源样例展开 754 次受控执行，与固定参考实现核对 754 个整题结果、900 个判据结果及 16 个概率值，差异为 0；详见 [结果摘要](../benchmarks/verification-summary.json) 和 [源版本清单](../benchmarks/sources.json)。原始数据、SQLite 和完整记录位于 Git 忽略的 `artifacts/benchmark-verification/`。
- 边界：MMLU 仅四题且传输被替换；CLINC 仅六个源样例，使用公开标签与 sklearn 参考聚合；IFEval 仅四类判据覆盖的 62 个样例及受控响应变体。以上验证平台契约，不评价模型能力或证明全量官方复现；BFCL/BEIR/τ-bench、后台恢复调度、用户数据迁移和权限系统尚未实现。SQLite 仅在 Node 24.14.1 / SQLite 3.51.2 的当前单机环境验证，内置模块仍有实验性警告。
- 真实模型验证：CLEF 已通过新持久链路完成 10 个实际请求，MMLU 4 题正确 3 题，CLINC 6 条全对（含 3 条 OOS）；原文、概率和 usage 已落盘并重开读取。派生协议和小样本范围见 [实测摘要](../benchmarks/clef-live-summary.json)，IFEval 未运行。
- 后续入口：在上述链路之上增加持久调度，不重做任务、执行和证据模型。

## 3. 后续切口候选

以下是按依赖排序的工作包；每周开始只选一个并补充当周完成条件，不作为固定周数承诺。

| 顺序 | 最小交付 | 关键验证 |
| --- | --- | --- |
| A | 单 Worker 持久领取与恢复，页面改查服务端状态 | 关页面继续；原文已保存时恢复只评分；未知在途请求不静默重发；旧 lease 不覆盖新结果 |
| B | 从一套真实 CLEF 方案接入完整证据链，随后扩至多方案 | 凭据隔离；协议契约；同任务配对；错误分类与预算限制；保留全部尝试 |
| C | 明确一次基线/候选回归和一条关键行为门禁 | 逐例退步可定位；规则预先冻结；证据不足不通过；结论版本绑定可校验 |
| D | 项目身份、授权和审计接入共享工作流 | 越权受阻；服务身份权限受限；政策/基线/例外变更可审计；共享前完成 |
| E | 将用户数据迁移、备份恢复、运行可观测性和 CI 串成部署交付 | 去重与来源可核对；故障恢复/回滚演练；在明确容量和恢复目标下测量 |
| F | 增加任务编辑、复核和生产反馈所需的下一个具体用例 | 新版本不修改旧结论；标签来源/数据划分可追踪；反馈形成新测试版本 |

身份/项目范围与凭据约束从第一周的数据和应用边界保留，D 是共享访问能力的完成点，不是首次考虑这些约束。备份、诊断等同样随存储/执行增量建设，E 汇总验证其部署可用性。

## 4. 计划维护规则

只展开当前周；其余保持工作包粒度。完成一周后，将本周目标、提交、证据和剩余问题压缩为一条周记录，再展开下一周，避免积累平行路线和过期计划。

生产首发逐项检查架构第 1.3 节的 Q1–Q6，并记录支持规格和验证证据。某个切口跑通、测试通过或一周结束，都不自动升级为生产交付完成。
